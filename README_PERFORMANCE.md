# Оптимизация времени выполнения

Основной локальный поиск `data_tenders` переведён с полного прохода по всем записям на хеш-индексы:

- `param + model + voltage` -> O(1)
- `param + model` -> O(1)
- `param` -> O(1)

Для нечёткого совпадения оставлен резервный путь; он запускается только когда точный индекс не дал кандидатов.

Дополнительно:

- нормализация строк и вычисление ключей кэшируются через `lru_cache`;
- модель и напряжение документа вычисляются один раз, а не для каждой строки;
- профиль `data_tenders` и полный AI-контекст кэшируются в памяти;
- Vision работает с дисковым SHA1-кэшем изображений;
- повторное добавление Vision-записей выполняется через set, а не через `any()` по всему списку записей;
- один GigaChat client переиспользуется для серии Vision-запросов;
- геометрический OCR PDF остаётся только там, где требуется определить координаты ячеек.

Важно: сетевые вызовы GigaChat/Vision нельзя ускорить локальным O(log n)-поиском. Основное ускорение здесь достигается сокращением числа API-вызовов, повторных OCR и повторных проходов по документам.
