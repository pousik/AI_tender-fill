# Профильный pipeline заполнения

Новая логика заполнения:

1. Один раз читается `data_tenders` и строится индекс технических данных.
2. Для текущего тендера строится `product_signature`:
   - `product_type`;
   - `model` / `ТРГ-УЭТМ-<класс напряжения>`;
   - `voltage_class`;
   - `insulation_types`;
   - `insulation_colors`.
3. Технические записи берутся только из профиля выбранного изделия.
4. Точное соответствие параметра выполняется через O(1) индекс.
5. Если для поля есть несколько допустимых кандидатов/составное значение,
   алгоритм не выбирает случайный вариант — поле передается GigaChat.
6. GigaChat получает контекст документа и выбранного профиля `data_tenders`
   и используется только для перепроверки/заполнения неоднозначных и нетипичных полей.
7. БД остается только хранилищем сохраненных специалистом шаблонов.

Основные реализации:
- `services/data_tenders_knowledge.py` — профиль и индексы `data_tenders`.
- `services/search_docx_AI.py` — профильный первичный проход DOCX + AI fallback.
- `services/search_pdf_AI.py` — тот же профильный первичный проход PDF.
- `services/template_knowledge.py` — только шаблоны специалиста.
