# Полный контекст data_tenders для GigaChat

Источником констант и технических эталонов является папка `data_tenders/` рядом с проектом.
SQLite (`transformers_legacy.db`) не используется как источник констант в первичном проходе.

## Что получает GigaChat

Для DOCX и PDF каждый AI-запрос получает:

1. полный извлечённый контекст текущего тендерного документа;
2. все строки текущего документа и результат первичного алгоритмического прохода;
3. полный корпус всех DOCX из `data_tenders/` — все таблицы, с устранением повторов merged-ячеек;
4. список встроенных изображений/чертежей каждого эталонного DOCX;
5. OCR текста изображений, если он уже есть в кэше или включён параметром `DATA_TENDERS_MAX_IMAGE_OCR`.

Для обычной работы OCR изображений не запускается на каждом тендере. Это сделано специально, чтобы не замедлять обработку.

## OCR изображений

При необходимости заранее прогреть OCR:

```powershell
$env:DATA_TENDERS_MAX_IMAGE_OCR="16"
python -c "from services.data_tenders_knowledge import get_data_tenders_knowledge; get_data_tenders_knowledge().build_full_context(include_images=True)"
```

OCR сохраняется в `data_tenders/.image_ocr_cache.json` и затем повторно не выполняется, пока исходный DOCX не изменился.

По умолчанию `DATA_TENDERS_MAX_IMAGE_OCR=0`, поэтому при запуске тендера используются все таблицы и каталог изображений без тяжёлого OCR.

## Логика AI

`требование -> первичное сопоставление с data_tenders -> полный контекст data_tenders + текущий документ -> GigaChat -> заполнение`

GigaChat обязан выбирать конкретное значение из эталона только при согласовании с типом/напряжением/исполнением и самим требованием. Строки без требования не заполняются произвольным значением из справочника.
