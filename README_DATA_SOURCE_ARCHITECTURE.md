# Архитектура источников данных

## Источники

1. `data_tenders/` — единственный источник технических характеристик изделия.
   Отсюда берутся типоисполнение, напряжение, климат, изоляция, токи, частоты,
   габариты, массы, данные из таблиц и данные, распознанные GigaChat Vision с
   изображений/чертежей.
2. SQLite/БД — только хранилище ранее заполненных специалистом шаблонов:
   `Tender` и `TenderParameter`. Эти записи используются для быстрого применения
   полностью/частично совпавшего шаблона и для последующего обучения шаблонов.
3. GigaChat — второй интеллектуальный уровень. Он получает требования текущего
   документа, найденные записи `data_tenders` и контекст документа и используется
   для разрешения неоднозначностей/связей. GigaChat не является самостоятельным
   источником констант.

## Запрещённые источники в обычном заполнении

`KnowledgeEntry`, `TrTypeRule`, `VoltageClass`, `Climat`, `IsolType`, `IsolColor`,
`ParameterProfile`, `ProfileParameter`, `FieldRule` и старые профильные значения БД
не используются как источник технических констант в DOCX/PDF-пайплайне.

## Приоритет

`DB_TEMPLATE` > `DATA_TENDERS` > `AI_CONTEXT` > пусто.

Если найден шаблон специалиста, его значения применяются, а остальные пустые поля
не заполняются автоматически. Если шаблона нет, первично ищется значение в
`data_tenders`; при неоднозначности поле передаётся GigaChat.

## Обучение

После редактирования специалистом сохраняются только финальные значения без `**`
в шаблонную БД. Удалённое специалистом значение удаляется из соответствующего
шаблона, чтобы оно не восстановилось при следующем запуске.
