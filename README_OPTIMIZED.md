# Оптимизированный pipeline

## Источники
- data_tenders — единственный источник технических характеристик.
- БД — только сохранённые специалистом шаблоны.
- GigaChat — второй уровень сопоставления/уточнения.

## Что ускорено
1. Индекс data_tenders строится один раз за процесс; `refresh()` больше не делает `rglob()+stat()` на каждом lookup.
2. Модель и напряжение вычисляются один раз на документ.
3. `get_constant()` больше не сканирует весь текст документа на каждой строке.
4. Точный lookup data_tenders — O(1) по хеш-индексам.
5. Полный AI-контекст data_tenders кэшируется.
6. При найденном шаблоне БД технический pipeline и AI полностью пропускаются.
7. GigaChat получает только незаполненные поля, но `global_summary` сохраняет все строки документа для зависимостей.
8. Если один AI-запрос слишком велик, размер чанка подбирается бинарным поиском, чтобы сократить количество API calls.
9. Vision остаётся кэшируемым и не запускается повторно без явного live-режима.
10. В PDF исправлена ошибка `alg_is_template` и удалён лишний legacy context из рабочего пути.

## Управление обновлением data_tenders
По умолчанию индекс считается неизменным во время одного запуска.
Для принудительной проверки файлов используйте:

`DATA_TENDERS_REFRESH_CHECK=1`

или программно:

`get_data_tenders_knowledge().refresh(force=True)`

## Предварительная индексация изображений
Чтобы один раз распознать изображения через GigaChat Vision и сохранить кэш:

`python preprocess_data_tenders.py`
